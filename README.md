# DM Hunter

Монитор NFT-подарков Telegram с поиском номеров через официальный Bot API `getUniqueGift`. Ищет свежие номера в выбранных коллекциях, проверяет редкость модели и фона, присылает подходящие подарки в ваш личный Telegram-бот. В уведомлении есть подарок, характеристики, публичный владелец и кнопка открытия его чата с готовым предложением.

Market Sniper и Getgems удалены: эта версия посвящена мониторингу подарков. Автоматических покупок и отправки сообщений владельцам нет. Нажатие кнопки открывает черновик в Telegram; отправку подтверждаете вы. Поддержка подстановки текста зависит также от используемого клиента Telegram.

## Обновление до v5.1.0

1. Закройте старую программу через `Ctrl+C` или закройте окно.
2. Скопируйте файлы из папки `DM-Hunter-v5` нового архива в вашу прежнюю папку программы с заменой.
3. Запустите `START_TELEGRAM.bat` (или `START.bat` для графического окна).

В архиве теперь только `config.example.json`, **файла `config.json` и базы нет**: ваши локальные настройки и история при замене файлов сохраняются. На чистом запуске нужные файлы создаются программой. Если токен уже настроен, повторный ввод не требуется. В журнале должна появиться строка `Источник номеров и характеристик: Telegram Bot API getUniqueGift`, затем результаты поиска номеров.

Живой разбор публичных страниц и переход от поиска к обходу проверены. Контракт Bot API проверен по официальной документации и локальным тестам, включая неизвестные подарки, ошибки авторизации, лимиты, отсутствие владельца и очередь доставки. Реальный запрос с вашим токеном выполняется только на вашем компьютере; в среде разработки его нет. Работа страницы владельца и наличие публичного username зависят от Telegram — их нельзя гарантировать для каждого подарка.

## Быстрый запуск в Windows

1. Установите **Python 3.10 или новее** с [python.org](https://www.python.org/downloads/). При установке включите `Add Python to PATH`, `pip` и `Tcl/Tk and IDLE`.
2. Полностью распакуйте архив в отдельную папку, доступную для записи. Не запускайте программу из окна архиватора.
3. Запустите `START.bat`. Первый запуск создаст `.venv` и установит зависимости — для этого нужен интернет. Python автоматически не скачивается.
4. Заполните Bot Token и личный Chat ID, сохраните настройки, проверьте связь с ботом и запустите мониторинг.

При проблеме окно запуска покажет ошибку. Если Python в старой `.venv` больше не работает, закройте приложение, переименуйте `.venv` и запустите `START.bat` снова. Настройки и база мониторинга находятся вне `.venv`.

## Если появляется ошибка `Can't find a usable init.tcl`

Это ошибка Tcl/Tk в установленном Python или путях к его библиотекам. Она мешает открыть окно. Программа ищет Tcl/Tk в базовой установке Python и исправляет неверные пути в среде своего процесса, когда необходимые файлы существуют. Отсутствующие библиотеки она не скачивает.

**Быстрый запуск без окна:** запустите `START_TELEGRAM.bat`. Он не использует Tkinter, запросит недостающие Bot Token и личный Chat ID в консоли и сохранит настройки. При вводе токена символы скрыты. Откройте своего бота, отправьте `/start`; после настройки мониторинг стартует автоматически. Используйте `/status` и `/stop` в боте, а для полного закрытия — `Ctrl+C` в консоли. Оставляйте консоль открытой.

Если `config.json` уже заполнен, повторного запроса токена не будет. Если нужны другие значения, измените этот файл при закрытой программе. В обычном `START.bat` при ошибке Tcl и доступной консоли предусмотрен такой же переход в режим без окна.

**Восстановление графического окна:** откройте установщик используемой версии Python с python.org → Modify → включите `Tcl/Tk and IDLE`. Если компонент уже выбран, выполните Repair. Проверьте базовый Python командой `python -m tkinter`: должно открыться тестовое окно. Если Python переносили вручную в другую папку, переустановите его штатным установщиком. Затем, при закрытом DM Hunter, удалите только папку `.venv` в папке программы и запустите `START.bat` снова. Базу и `config.json` сохраняйте.

Для обновления распакуйте сборку в новую папку. Закройте старый экземпляр и перенесите из старой папки `config.json` и `hunter.sqlite3`, если уже пользовались программой. Копируйте базу только после закрытия приложения.

## Подключение своего Telegram-бота

1. Создайте бота через [@BotFather](https://t.me/BotFather), командой `/newbot`. Скопируйте выданный токен в Bot Token.
2. Узнайте **свой числовой Telegram ID**, например через [@userinfobot](https://t.me/userinfobot). Вставьте его в Chat ID. Нужен положительный ID личного чата, а не username, номер телефона или отрицательный ID группы.
3. Откройте **созданного вами бота** и нажмите `/start`: бот не может первым начать личный диалог.
4. Сохраните настройки в DM Hunter и выполните тест Telegram.

В вашем боте доступны `/start` и `/help` для справки, `/start_scan` для запуска, `/stop` для остановки сканирования, `/status` для состояния и соответствующие кнопки. Команды принимаются только из личного чата указанного пользователя. Не запускайте с тем же токеном другую программу получения обновлений и не включайте webhook: это конфликтует с long polling.

Токен хранится локально в `config.json`. Не публикуйте этот файл и не пересылайте его вместе с архивом. В журнале движок скрывает текущий токен. На Linux файл настроек сохраняется с правами `0600`.

## Коллекции, фильтры и предложение

Коллекции указываются через запятую как в ссылках `https://t.me/nft/CandyCane-123`: например, `CandyCane, JingleBells`. Вводить полные ссылки или отображаемые названия с пробелами не нужно.

Подарок подходит, если у него есть публичный username владельца и выполняется **хотя бы одно** условие:

- Редкость модели не больше заданного порога.
- Редкость фона не больше заданного порога.
- Имя фона точно совпадает с одним из указанных, без учёта регистра.

Значения редкости показаны в процентах. Если страница Telegram использует промилле, приложение пересчитывает их: `5‰ = 0,5%`. Пустые или неизвестные значения не считаются редкими при обычных порогах. При пороге `0` соответствующий фильтр редкости отключён; список фонов можно оставить пустым. Фон `Black` не означает автоматическое совпадение с `Black Hole`.

Для черновика предложения допустимы подстановки:

- `{gift}` — коллекция и номер подарка.
- `{number}` — номер.
- `{collection}` — slug коллекции.
- `{model}` и `{backdrop}` — модель и фон.

Пример: `Привет! Интересует твой {gift}, модель {model}. Продажа актуальна?`

## Как устроен мониторинг

При настроенном токене номера и характеристики берутся из официального [getUniqueGift](https://core.telegram.org/bots/api#getuniquegift). Этот метод не возвращает владельца: username подходящего подарка дополнительно ищется на публичной странице. Без доступного username уведомление с контактом не отправляется, а номер сохраняется для повторной проверки.

На первом запуске для каждой коллекции определяется доступная граница номеров и проверяются последние `lookback` номеров (по умолчанию 50). Первый поиск, особенно для пяти коллекций сразу, может занять несколько минут: запросы намеренно ограничены по частоте. После этого проверяются следующие номера; положение сохраняется в SQLite и восстанавливается после перезапуска.

Публичный порядковый номер — **косвенный признак недавнего улучшения**, а не подтверждённое время события. Публичная страница не даёт надёжной даты улучшения. DM Hunter не заявляет, что находит все улучшения за конкретный временной интервал.

Небольшие пропуски не останавливают обход: проверяются соседние номера. Пропущенные и временно скрытые страницы сохраняются для повторной проверки на 24 часа. Периодически заново проверяется граница коллекции. HTTP 429 и 403 обрабатываются как явные ограничения API/страниц. Пустой HTML с HTTP 200 не считается доказательством ограничения частоты: карточка перепроверяется один раз, затем данные владельца откладываются. Для поиска границы через Bot API HTML не нужен. Ошибка повторного поиска границы не блокирует обычный обход от сохранённой позиции. При сетевом сбое уже подтверждённые опорные номера остаются в памяти до завершения поиска; `/status` показывает коллекции без данных.

Пропуски длиннее `gap_window`, скрытые владельцы, изменения HTML Telegram и ограничения сервера могут влиять на полноту поиска. Гарантии 100% покрытия нет.

Кнопка остановки завершает задачи сканирования; повторный запуск возобновляет работу без второго параллельного сканера. **Очередь уже найденных уведомлений продолжает доставляться после остановки сканирования**, пока приложение открыто. Чтобы прекратить все подключения, закройте программу.

Без токена доступен ограниченный локальный режим по HTML, для которого поиск свежих номеров может быть неполным. Без Chat ID можно сканировать через настроенный токен локально: находки видны в таблице и сохраняются в очереди. Для их последующей доставки заполните настройки Telegram и сохраните их. Интернет для API и публичных страниц всё равно необходим.

## Сохранение и доставка

В папке приложения автоматически создаются:

- `config.json` — настройки.
- `hunter.sqlite3` и служебные файлы SQLite `-wal`, `-shm` — позиции, история находок, пропуски и очередь.
- `dm_hunter.log` и его ротации — журнал работы с ограничением размера.
- Файл блокировки — защита от одновременного запуска двух экземпляров **из одной папки**. Он остаётся на диске после закрытия; наличие файла само по себе не означает работающий процесс.

Не удаляйте базу для обычного перезапуска: иначе исчезнут позиции и защита от повторных уведомлений. Для резервной копии сначала закройте приложение, затем копируйте папку. Файл базы хранит ссылки и владельцев найденных подарков.

Уведомления сначала записываются в SQLite. При сетевой ошибке остаются в очереди и отправляются повторно с увеличением паузы; лимиты Telegram `429` учитываются. Подтверждённые сообщения повторно не отправляются. Есть стандартное исключение: если приложение аварийно завершится **после отправки сообщения, но до записи подтверждения в SQLite**, при следующем запуске возможен дубль. Это доставка «как минимум один раз».

## Дополнительные настройки

Основные параметры доступны в интерфейсе. Закрыв приложение, дополнительные значения можно изменить в `config.json`:

| Параметр | По умолчанию | Назначение |
|---|---:|---|
| `poll_interval` | 8 | Пауза после достижения границы, секунды. |
| `request_interval` | 1.0 | Минимальный общий интервал между запросами NFT-страниц, секунды. |
| `lookback` | 50 | Сколько последних номеров проверить при первом запуске коллекции. |
| `scan_batch` | 20 | Размер обычного прохода. |
| `gap_window` | 10 | Проверяемое окно пропущенных номеров. |
| `rescan_interval` | 900 | Период повторного поиска границы, секунды. |
| `initial_ids` | `{}` | Опорные номера для поиска, например `{"CandyCane": 222000}`. |

Опорный номер не ограничивает поиск сверху. После появления сохранённого курсора `initial_ids` не сбрасывает положение. Сохраняйте файл как корректный JSON. Повреждённый файл настроек не заменяется молча настройками по умолчанию.

## Linux и работа без окна

Нужны Python 3.10+, модуль `venv` и, для окна, Tkinter. Например, в Debian/Ubuntu системные пакеты называются `python3-venv` и `python3-tk`. Установите их штатным менеджером пакетов.

```bash
bash start.sh
```

После настройки `config.json` можно работать без GUI:

```bash
bash start.sh --headless --autostart
```

В Windows тот же режим:

```bat
START.bat --headless --autostart
```

Без `--autostart` мониторинг запускается кнопкой или командой вашего бота. В режиме `--headless` окно и Tkinter не требуются; останавливайте процесс через `Ctrl+C`. Сам по себе этот режим не устанавливает системную службу и не обеспечивает работу после закрытия терминала.

## Проверка и зависимости

Обычный запуск использует `requirements.txt` с совместимыми диапазонами. `requirements-lock.txt` содержит точные версии зависимостей, использованные при проверке на Python 3.12 / Linux; при необходимости установите их вручную в `.venv`.

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Проверено: 82 автоматических теста, графический цикл запуск → находки → остановка → повторный запуск → закрытие на Linux с тестовым источником, а также разбор реальных публичных страниц Telegram. Windows-launcher проверен статически; доставка с вашим токеном требует теста из интерфейса.

В Windows используйте `.venv\Scripts\python.exe` вместо `.venv/bin/python`. Локальные тесты не требуют токена и не отправляют сообщения. Отдельная успешная проверка публичных страниц не заменяет проверку доставки с вашим токеном: её выполняет кнопка теста Telegram.
